# 一、产品概述

## 1.1 产品定位
**抖小夹是一款面向社交媒体收藏场景的 AI 个人知识管理与应用工具。**

帮助用户将小红书、抖音、B站等平台收藏的碎片化内容，转化为可以被智能整理、检索和复用的个人知识资产。

产品不依赖特定社交平台的内部收藏夹接口，通过跨平台快捷采集实现知识输入，并利用 AI 完成后续的知识管理与应用。

**核心价值：让收藏不止于保存，而是真正能够被找到、理解和使用。**

## 1.2 目标用户
主要面向具有社交媒体知识收藏习惯的年轻用户，如大学生、职场新人、内容创作者等。

用户特征：
- 经常收藏教程、攻略、经验和工具推荐。
- 收藏内容分散在不同社交平台。
- 缺乏主动整理收藏夹的习惯。
- 遇到实际问题时，难以快速找到过去收藏的信息。
- 希望将收藏的方法应用于学习、工作或生活。

## 1.3 核心用户痛点
| 用户痛点 | 问题描述 | 对应产品能力 |
|---|---|---|
| P1 收藏杂乱 | 内容持续积累，分散在不同平台，整理成本高 | AI 自动分类与深度整理 |
| P2 检索困难 | 记得收藏过某项知识，却难以快速查找 | RAG 智能检索 |
| P3 知行脱节 | 收藏了有用的方法，但难以将其转化为实际能力 | Skill 生成与复用 |
| P4 内容闲置 | 收藏后长期不再使用，缺少合适的激活时机 | AI 智能唤醒 |

以上为当前产品设计的问题假设，尚不等同于已经通过用户研究验证的结论。

## 1.4 产品设计目标
**目标一：降低知识采集与整理成本**

通过系统快捷交互与 AI 自动归类，让用户无需频繁切换应用或手动整理。

**目标二：提高个人知识获取效率**

通过自然语言检索与持续对话，让用户直接从收藏内容中获得答案。

**目标三：促进知识向实际能力转化**

通过 AI 识别用户意图，将收藏的方法封装为可复用的 Skill。

# 二、产品整体架构

## 2.1 核心功能
| 功能 | 主要作用 |
|---|---|
| 01 AI 智能分类 | 自动理解、归类和管理收藏知识 |
| 02 RAG 智能问答 | 基于收藏内容进行检索、总结与连续对话 |
| 03 Skill 创建与管理 | 将个人知识转化为可重复调用的能力 |
| 04 AI 智能唤醒 | 在适当时机引导用户重新使用知识 |

四个功能之间不是严格的线性关系。AI 分类为知识库建立基础；RAG 问答负责知识获取；Skill 负责知识应用；智能唤醒则在不同使用阶段提供辅助。

## 2.2 产品信息架构
采用两个主要页面，加一个全局 AI 助手。

### 顶部导航
**知识库｜我的 Skill**

知识库页面：知识主题分类、知识卡片浏览与详情、AI 深度整理、分类及内容管理。

我的 Skill 页面：已创建 Skill 列表、Skill 详情、Skill 编辑/试运行/导出、新建 Skill 入口。

### 底部全局 AI 入口
「抖小夹 AI」对话入口固定在页面底部。
- 知识库和我的 Skill 页面均可唤起。
- 默认是轻量输入栏。
- 点击后展开半屏 AI 面板。
- 支持进一步展开全屏。
- 支持连续对话。
- 根据当前页面动态推荐快捷操作。

**设计原则：页面负责展示和管理内容，AI 对话负责理解用户意图并辅助完成操作。**

# 三、功能一：跨平台知识采集与 AI 分类

## 3.1 功能目标
解决用户在不同社交媒体中收藏知识分散、手动整理成本高的问题。采用「用户主动采集单篇内容，AI 自动处理」模式，不将自动同步全部历史收藏夹作为当前主要功能。

## 3.2 内容采集方式
### 方式 A：截图快捷采集
用户浏览社媒内容时，通过截图或系统快捷指令采集当前画面。建议支持：
- 手机截屏后分享至抖小夹。
- iOS 快捷指令结合背部轻点触发采集。
- Android 通过系统分享入口或支持的快捷操作采集。

后两类涉及系统权限与原生能力，需要单独验证。

### 方式 B：分享链接导入
用户从社交媒体复制或分享内容链接，导入抖小夹。系统尝试解析可访问的内容信息。

### 方式 C：应用内手动导入
用户打开抖小夹，上传截图、粘贴链接或输入文字，作为快捷采集之外的补充方式。

## 3.3 AI 自动处理流程
**用户采集内容 → 系统接收 → AI 解析 → 提取知识 → 推荐归类 → 保存知识卡片**
1. 识别内容类型、来源与可获取的信息。
2. 使用 OCR 或文本解析提取知识内容。
3. AI 生成简短标题、内容摘要与主题标签。
4. 优先匹配知识库中已有分类。
5. 没有合适分类时，建议创建新分类或暂存待整理。
6. 保存原始内容及 AI 处理结果。

截图只能基于实际可见的信息提取知识，不应假定系统读取了完整文章或视频。

## 3.4 收藏后的交互反馈
参考系统灵动岛或 Android 对应的实时状态展示能力。

**快捷采集 → AI 整理中 → 提示归类结果 → 用户按需调整**

例如：「收藏成功 · 已归类至求职面试」。用户可以查看内容、修改分类、撤回收藏。

**默认自动保存，不要求用户每次都点击确认。**

灵动岛、流体云等属于原生系统交互能力，Web Demo 可以模拟其视觉流程，但不能将模拟界面视为已经实现系统级接入。

## 3.5 知识存储结构
采用两级组织结构：**主题分类 → 知识卡片**。

例如，求职面试分类下包含交互设计面试技巧、STAR 回答方法、项目介绍经验。

每张知识卡片包含：标题、原始内容或截图、来源平台与原始链接（如可获取）、AI 摘要、关键知识点、主题分类与标签、收藏时间、内容完整性状态。

原始资料与 AI 生成的摘要应分别保存，避免后续知识检索失去依据。

## 3.6 AI 深度整理
用户可以从知识库首页或具体分类进入「AI 整理」。

**点击 AI 整理 → AI 分析当前内容 → 推荐整理方案 → 用户确认或修改 → 更新知识库**

AI 可以建议：调整知识分类结构、合并相似分类、识别重复内容、推荐未归类内容、创建必要的子分类。

应用前可预览整理变化，支持手动调整。未经确认，不得执行大规模删除、合并等影响用户数据的操作。

# 四、功能二：RAG 智能问答

## 4.1 功能目标
通过自然语言获取收藏中的知识，无需手动翻找文件夹和笔记。除知识检索，也支持理解、总结和持续追问。

## 4.2 AI 助手入口与形态
采用**全局底部 AI 输入栏 + 半屏对话面板 + 全屏对话**。

默认底部常驻轻量输入栏：「问问抖小夹，关于你的收藏…」。点击入口唤起半屏面板，不立即弹键盘，优先展示当前页面相关快捷问题、用户输入框、当前对话内容（如有）。对话中用户可根据内容长度主动展开全屏，支持连续追问、查看来源和返回知识库。

## 4.3 智能快捷提问
| 当前页面 | 快捷提问 |
|---|---|
| 知识库首页 | 帮我总结最近收藏的内容；找找我收藏过的面试技巧；根据收藏创建 Skill |
| 具体分类页面 | 总结这个分类；这个分类有哪些实用方法？；查找这个分类里的内容 |
| 单篇知识卡片 | 总结这篇内容；提取其中的关键方法；围绕这篇内容继续提问 |
| 我的 Skill 页面 | 根据收藏创建 Skill；帮我修改已有 Skill |

用户也可直接输入自然语言需求。快捷提问是 AI 对话能力的快捷入口，不单独构成另一套功能。

## 4.4 RAG 问答流程
**用户提问 → AI 理解意图 → 检索相关收藏 → 组织回答 → 展示来源 → 支持继续追问**

### A. 查找收藏
例如：「我之前收藏过哪些关于交互设计面试的内容？」优先展示相关知识卡片、摘要及来源。

### B. 知识问答
例如：「根据我收藏的内容，交互设计面试应该怎么回答项目冲突问题？」检索相关知识，整合结构化回答，并引用对应来源。

## 4.5 回答展示
采用 **AI 整理回答 + 相关来源卡片 + 后续追问**。来源卡片可进入知识详情或打开原始链接。用户可追问「第二个方法能详细解释吗？」；系统结合历史上下文理解，必要时重新检索。

## 4.6 AI 摘要
保留 AI 概括能力，不设计独立全局摘要模块。触发方式：分类/知识卡片点击「AI 概括」，或在对话中直接要求总结。结果统一展示于 AI 对话，可继续追问。

## 4.7 异常处理
- 未检索到内容：明确提示没有找到相关收藏。
- 内容不完整：提示答案仅依据已保存片段。
- 来源不足：不得将模型自身知识冒充个人收藏内容。
- 服务失败：保留用户输入，允许重试。
- 长对话：提供历史记录与重新开始对话能力。

# 五、功能三：Skill 创建与管理

## 5.1 功能定位
将收藏知识和方法转化为可重复调用的 AI Skill。**主要负责发现、生成、编辑、保存、轻量试运行和导出。** 不扩展为自主操作任意第三方应用的通用 Agent 平台。

## 5.2 Skill 的用户理解方式
普通用户无需先理解复杂技术概念，通过具体应用价值解释，例如「将收藏的面试技巧变成你的专属面试助手。」补充说明：「Skill 可以让 AI 按照你保存的方法重复完成类似任务。」创建后再展示结构与使用说明。

## 5.3 Skill 创建方式
两种触发方式，统一进入同一套 AI 对话创建流程。

### A. AI 主动推荐
主要场景：RAG 对话之后。例如用户要求「帮我整理收藏的面试回答技巧。」回答后 AI 识别知识有重复使用价值，可在结果底部展示「可以将这些方法变成一个面试回答优化 Skill。」点击进入创建流程，沿用对话上下文和引用知识。

辅助场景：分类中存在明确可复用方法时轻量推荐，不得单纯按收藏数量触发。

### B. 用户主动创建
入口包括对话快捷提问「根据收藏创建 Skill」、自然语言表达创建需求、我的 Skill 点击新建、分类页面选择创建 Skill。所有入口唤起统一助手，不设计另一套独立表单式创建系统。

## 5.4 Skill 创建完整流程
1. **明确任务目标：** 用户描述「我想创建一个能够帮助我模拟交互设计面试的 Skill。」AI 按需澄清。
2. **关联个人知识：** 检索并推荐收藏，用户可确认、添加、移除引用；缺少知识时明确提示，不假装依据充分。
3. **生成 Skill：** 基于目标和知识生成名称、描述、适用场景、输入要求、执行步骤、输出形式、引用知识、使用限制。
4. **预览与调整：** 对话中展示结构化卡片，可直接修改关键字段或通过自然语言调整，例如「面试问题更侧重系统交互设计。」
5. **轻量试运行：** 无外部工具依赖的 Skill 可输入示例任务测试，例如输入面试回答进行优化。需要外部工具或权限时，明确不能完整执行，仅检查结构和配置。
6. **保存或导出：** 保存到我的 Skill，支持生成符合目标兼容环境要求的 Skill 文件及必要参考资料。外部工具兼容性需具体验证，不能默认所有 AI 产品可运行同一个 Skill。

## 5.5 我的 Skill 页面
卡片包含名称、用途简介、相关知识主题、创建或更新时间、使用入口。详情支持查看完整 Skill、编辑、适用时轻量试运行、导出、删除。新建仍唤起全局 AI 面板。

## 5.6 Skill 与 RAG 的关系
同一助手承担不同任务：**RAG 回答当前问题；Skill 沉淀可重复执行的任务方法。** AI 识别意图。从回答转化 Skill 时复用相关收藏和任务上下文，避免用户重新输入全部内容。

# 六、功能四：AI 智能唤醒

## 6.1 功能目标
帮助用户重新利用已收藏知识，减少有价值内容长期闲置。

## 6.2 主要触发场景
- A 重复收藏相似知识：持续收藏同类教程/方法时，提示「你最近收藏了多篇面试技巧，要不要整理一下？」
- B 已有 Skill 可以更新：新增收藏与已创建 Skill 高度相关，提示「最近新增了几篇面试经验，要不要更新你的面试 Skill？」
- C 长期未使用的知识：在适当时机轻量回顾，不采用机械高频提醒。

## 6.3 交互原则
低打扰卡片/徽标/通知；说明具体价值；可忽略或关闭；不自动修改 Skill 或知识库；优先结合可判断的实际使用意图，而不只是收藏时长。

# 七、关键交互状态与异常处理

## 7.1 内容采集
正在接收、正在解析、自动归类完成、内容不完整、解析失败、重复收藏、保存失败。

## 7.2 知识整理
分类处理中、AI 推荐调整方案、用户确认修改、修改成功、撤回或取消、无需整理。

## 7.3 AI 对话
首次打开、快捷问题展示、生成中、检索结果、连续追问、无相关结果、请求失败。

## 7.4 Skill
创建引导、目标澄清、引用知识选择、生成中、预览编辑、试运行、保存成功、导出成功或失败、外部依赖不满足。

# 八、AI 能力与技术边界

## 8.1 核心 AI 能力
| 能力 | 输入 | 输出 |
|---|---|---|
| 内容识别 | 截图、文本、可访问链接内容 | 文本、主题、摘要 |
| 智能分类 | 知识及现有分类结构 | 推荐分类与标签 |
| 深度整理 | 分类和卡片集合 | 整理建议 |
| RAG 问答 | 问题、历史对话、检索内容 | 回答与来源 |
| Skill 生成 | 任务目标、引用知识 | 结构化 Skill |
| Skill 试运行 | Skill 规则、示例输入 | 执行结果或限制提示 |
| 智能唤醒 | 收藏及使用行为 | 有依据的提醒建议 |

## 8.2 技术实现建议
前后端分离。前端负责双页面、AI 半屏/全屏、知识卡片、Skill 预览编辑、状态反馈。后端负责解析、模型调用、存储、检索索引、RAG 工作流、Skill 生成导出。数据层包括分类、原始内容、知识卡片、对话、Skill 定义、Skill 引用关系。框架、模型、数据库和部署环境由 Codex 根据项目条件制定，不强制指定。

## 8.3 核心技术边界
1. 不依赖第三方未开放的收藏夹读取接口。
2. 不保证通过链接读取所有社媒内容。
3. 截图采集不等于完整文章/视频。
4. 不将模型幻觉内容保存为原始资料。
5. 涉及用户数据修改的操作提供确认。
6. 模型 API 密钥保存在安全服务端环境。
7. 不以复杂外部 Agent 执行为核心能力。
8. 灵动岛/流体云需原生验证，不视为纯 Web 默认能力。
9. Skill 导出与外部执行明确数据携带方式和目标平台兼容性。

# 九、核心体验验收标准
## 9.1 收藏与分类
新的、未预设内容可完成真实解析、保存、AI 分类；分类可查看修改。
## 9.2 知识库管理
可进入分类、查看原始内容和摘要、基本管理；深度整理基于实际数据建议，确认后更新。
## 9.3 RAG 对话
对真实收藏检索并回答，带来源；支持追问；无依据时正确提示。
## 9.4 Skill 创建
自然语言任务结合真实收藏生成结构化 Skill；可预览、修改、保存、导出；支持的文本任务可真实试运行。
## 9.5 体验完整性
主要流程具加载/成功/失败/空状态；不能完全依赖写死 Mock；平台权限和系统概念明确标注。

## AI整理分组预览（2026-10-19）
按用户提供的参考图，整理界面采用独立64px顶栏、IP检查概览、分组建议、底部固定确认栏；手机全屏、桌面限宽。按实际数据展示重复收藏、未分类内容、分类优化建议，无依据时不凑数量。支持逐项选择、修改归类、折叠分组、稍后处理、加载/空/失败状态。
重复组选择保留一条，其余副本软删除收起，原始记录仍保留；关联Skill引用重绑到保留项。分类合并保留全部资料并收起源分类。两类操作默认不选中，预览影响后二次确认，与归类调整在一个事务内提交，统一撤回。建议较晚收藏只作为服务端默认推荐顺序，不代表新帖或内容质量更高。
分类合并当前只在全库范围提供，有至少2组相同原文/链接，且覆盖较小分类60%以上才建议；不把分类名相近当成充分依据。分类内整理不触及其他分类。仅关键词/规则检查时明确标注未调用模型；真实模式归类使用模型，重复/合并依实际数据核对。

## Skill详情与卡片式创建（2026-10-19 用户最新调整）
Skill详情采用独立64px标题栏（返回/名称/编辑），隐藏首页主Tab和演示工具条，无搜索。主体顺序：简介→黑色导出Skill主按钮→完整定义（直接展开）→关联收藏；关联收藏使用现有知识卡片，无尾部管理/导出按钮，不放背景图。右上编辑支持重命名、简介、规则、引用修改及确认删除；删除不影响原收藏，可撤回。
主按钮一次导出ZIP，内含SKILL.md、skill.json、参考原文和许可说明。Markdown为可读规则，JSON为结构化备份；统一打包，不保证任意平台直接兼容，不包含模型密钥或图片/视频。移除详情顶部“非本轮AI生成”等状态提示，来源与限制仍在导出元数据中保留。演示Skill采用按ID稳定分配的IconPark图标/浅色主题，列表详情一致。

回答采用真实结果与来源校验完成后的段落渐入，不声称是模型Token级流式传输。支持减少动效。修复旧气泡外层16px padding造成头像顶部错位。
