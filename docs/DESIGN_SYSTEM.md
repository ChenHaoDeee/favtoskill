## 当前实施约定（2026-10-18）

原始视觉规范正文保留。以下为用户后续确认的实施规则，覆盖正文中的旧建议；历史补充移至 [UI_DECISIONS_HISTORY.md](UI_DECISIONS_HISTORY.md)。

- 通用图标统一 IconPark，常用操作20/24px。用户星星IP独立保存为品牌资源，文件夹轮廓为装饰图形。
- 首页、Skill列表与分类页顶栏统一64px + Safe Area。首页/Skill列表为双导航；分类内左侧返回、居中分类名、右侧搜索后接编辑。
- 首页顺序：未分类知识→AI整理→全部分类。前两栏76px等高。AI整理无描边、暖白到浅绿渐变；新建为全部分类右侧无描边加号及“新建文件夹”文字。
- 文件夹采用白底后层、三张真实封面中层、浅色面板前层。封面竖版宽3高4（CSS 3/4），面板约58%；图标无背景、正方形、深色随分类色系；图标文字间距手机13px、桌面18px。
- 新建及文件夹设置支持名称、10种IconPark图标、5种低饱和颜色，预览与保存一致，重启保留；旧分类未指定样式时按名称映射。
- 分类摘要采用紧凑浅绿容器，仅在“分类摘要”标题前放小AI星星，不设左侧大图标。分类管理从搜索右侧编辑进入，移除需确认。
- 知识卡白底、两行标题、底部平台来源。演示平台混合展示抖音/小红书/B站；使用独立展示字段，保留原始来源追踪。
- 全局AI入口为无左图标胶囊输入框、箭头内置。默认/半屏/全屏共用底部锚点；打开不立即唤键盘，支持拖动调高低，全屏隐藏手柄、使用对角箭头缩放。
- 对话欢迎区及消息头像用用户透明IP素材；快捷提问单列、每项随文案宽度适应、无尾箭头，中性背景。
- 输入框不显示粗外框，仅用1px细边框反馈焦点；按钮等键盘操作保留柔和细焦点提示。主要触控区域至少44px。

## 01. 产品定位与设计理念

### 1.1 产品定位

FavToSkill（藏点本事）是一款面向年轻用户的 AI 收藏管理与知识转化工具。

它帮助用户将分散在短视频、社交媒体等平台中的收藏内容，通过 AI 自动整理、分类、总结、检索和 Skill 生成，转化为可查找、可理解、可复用的个人知识与能力。

#### 核心目标用户

- 大学生、职场新人等年轻群体
- 有大量知识类内容收藏习惯的用户
- 希望管理知识，但不习惯复杂知识管理工具的普通用户
- 对 AI 工具感兴趣，但不一定理解复杂 AI 技术概念的用户

#### 核心用户问题

1. 收藏很多，但很少重新查看。
2. 收藏内容分散、杂乱，手动整理成本高。
3. 想使用时难以快速找到对应内容。
4. 知识碎片化，难以转化为实际行动或可复用的方法。

#### 产品核心理念

**From Favorites to Skills — 让收藏，变成本事。**

核心体验路径：

`收藏内容 → AI 自动整理 → 知识理解与检索 → Skill 转化与使用`

### 1.2 品牌视觉定位

品牌定位：

**轻盈有序的趣味知识工具（Playful Minimal Productivity）**

这是一种融合年轻化内容产品与现代 AI 效率工具的视觉设计语言。

整体设计应同时具有以下特点：

- **年轻 Young**：现代、轻快、具有一定个性。
- **轻松 Friendly**：自然亲切，没有传统知识管理软件的学习压力。
- **聪明 Smart**：通过清晰的界面组织和适当的 AI 反馈传达智能感。
- **有序 Organized**：布局清晰、信息分层明确。
- **可信 Reliable**：内容易读、操作明确、结果可溯源。

#### 视觉设计原则

采用 **80% 简洁克制 + 20% 品牌趣味** 的整体策略。

80% 用于基础布局、信息组织、文字阅读与功能操作。

20% 用于品牌 Logo、核心操作、AI 反馈、Skill 展示与轻量交互动效。

界面应该让用户感觉自己在使用一个更聪明的收藏夹，而不是学习一套复杂的知识管理系统。

## 02. 品牌识别系统 Brand Identity

### 2.1 品牌名称

中文标准名称：

**藏点本事**

英文标准名称：

**favtoskill**

英文名称推荐采用小写字母，营造轻松、亲切的品牌感。

#### 品牌口号

**让收藏，变成本事。**

其他可用于产品运营和引导的辅助文案：

- 好东西，值得好好收藏。
- 收藏不只是存起来。
- 让每一次收藏都有用。
- 把收藏的知识变成自己的办法。

### 2.2 Logo 设计概念

#### 核心图形：几何书签 + 折角展开

Logo 从书签形态出发，通过折角、展开、延伸等几何变化，表现收藏内容向个人能力转化的过程。

三个核心视觉概念：

1. **收集**：书签代表用户保存的内容。
2. **整理**：几何图形的排列、归并与组织。
3. **转化**：折角展开或向上延展，代表知识转化为能力。

#### Logo 风格要求

- 采用现代几何设计语言。
- 简洁、圆润、易于辨识。
- 优先使用平面化设计。
- 使用品牌青柠绿与深墨色。
- 保证小尺寸下仍有清晰识别度。
- 可扩展为 App Icon、AI 状态图形和功能标记。

#### 不推荐

- 传统书本、灯泡等过于通用的符号。
- 复杂的机器人头像。
- 大量 AI 四角星装饰。
- 高光、金属、玻璃质感。
- 过度复杂的拟物形态。

### 2.3 品牌辅助图形

从 Logo 中提取以下视觉元素：

- 圆角矩形
- 书签缺口
- 折叠与展开的边角
- 层叠的内容卡片
- 有序排列的几何模块

辅助图形可以用于：

- 启动页
- 空状态
- 引导页
- AI 处理中
- Skill 生成成功反馈
- 品牌宣传物料

辅助图形应保持轻量，避免抢占主要内容的视觉注意力。

## 03. 色彩系统 Color System

### 3.1 色彩定位

采用：

**暖白底色 + 深墨色文字 + 青柠绿品牌色**

整体氛围为明亮、自然、轻盈、年轻。

避免使用传统 AI 产品常见的大面积蓝紫渐变。

### 3.2 品牌核心色

| 色彩名称 | 色值 | 用途 |
|---|---|---|
| Brand Lime | `#D5F57A` | 品牌主色、AI 核心按钮、重要选中状态 |
| Deep Ink | `#202620` | 主文字、主按钮、品牌深色背景 |
| Warm White | `#F8F9F5` | 应用整体背景 |
| Pure White | `#FFFFFF` | 卡片、浮层、输入框 |

品牌青柠绿是整套视觉系统中最有辨识度的色彩。

但不能因为它是品牌主色，就让所有按钮和卡片都使用青柠绿。

#### 使用原则

- 页面背景以暖白为主。
- 内容卡片以白色为主。
- 普通主要操作优先使用深墨色。
- 与 AI 相关的核心操作可以使用青柠绿。
- 少量选中态和关键结果使用青柠绿强调。
- 不用高饱和青柠绿大面积铺满内容页面。

### 3.3 中性色

| Token | 色值 | 用途 |
|---|---|---|
| Background Primary | `#F8F9F5` | 页面背景 |
| Background Surface | `#FFFFFF` | 内容容器 |
| Background Secondary | `#F1F3EE` | 次级模块背景 |
| Border Default | `#E5EAE1` | 边框、分割线 |
| Text Primary | `#202620` | 主要文字 |
| Text Secondary | `#647064` | 次要文字 |
| Text Tertiary | `#899188` | 辅助信息、占位符 |

### 3.4 辅助色

| Token | 色值 | 用途 |
|---|---|---|
| AI Surface | `#EFF8D8` | AI 信息卡片与摘要区域 |
| Success | `#3F7C5B` | 操作完成、成功反馈 |
| Warning | `#B27729` | 温和提醒 |
| Error | `#C44E4E` | 操作错误 |
| AI Soft Highlight | `#F3F9E6` | AI 轻量背景装饰 |

#### 色彩规范

- 青柠绿背景搭配深墨色文字。
- 不在浅绿色按钮上使用白色文字。
- 常规正文必须确保足够的对比度。
- 状态信息不能仅依靠颜色识别，需要结合图标或文字。
- 对比度目标：普通文本不低于 4.5:1，大号文本不低于 3:1。

### 3.5 深色模式

V1.0 优先完善亮色模式。

暂不要求所有页面制作深色模式。

如果后续增加 Dark Mode，需要建立完整的语义化颜色映射，而不是直接将页面背景反色。

## 04. 字体系统 Typography

### 4.1 字体选择

#### 中文字体

优先使用：

- PingFang SC
- Source Han Sans SC
- Noto Sans SC

#### 英文字体

优先使用：

- Inter

#### 字体风格

- 现代无衬线字体。
- 保持清晰、自然、亲切。
- 通过字号、字重和留白建立信息层级。
- 不使用卡通字体。
- 不使用大面积手写字体。

### 4.2 字体层级

| 层级 | 字号 | 字重 | 场景 |
|---|---|---|---|
| Display | 32px | Bold 700 | 品牌展示 |
| Page Title | 24px | Semibold 600 | 页面主标题 |
| Section Title | 18px | Semibold 600 | 功能区标题 |
| Card Title | 16px | Medium 500 | 收藏分类、Skill 名称 |
| Body | 14px | Regular 400 | 正文、描述、AI 摘要 |
| Caption | 12px | Regular 400 | 来源、时间、数量 |
| Small Label | 11px | Medium 500 | 极少量紧凑标签 |

### 4.3 排版原则

- 页面标题突出但不夸张。
- 中文正文建议行高 1.5–1.6。
- 卡片标题最多显示两行。
- 内容预览采用省略与展开机制。
- 文字以左对齐为主。
- 尽量避免多个不同字重混杂。
- 信息层级优先通过字号、间距和对比度区分。

## 05. 图标系统 Iconography

### 5.1 设计风格

采用：

**圆润、简洁的几何线性图标**

建议统一基于 Lucide 图标体系进行设计。

#### 基本规范

- 基础网格：24 × 24px
- 常规描边：1.75–2px
- 常用尺寸：20px / 24px
- 统一端点与转角风格
- 普通图标使用深灰色或次级文字色
- 选中图标可使用实心样式或浅绿色背景

### 5.2 图标语义

| 功能 | 建议图形 |
|---|---|
| 收藏 | Bookmark |
| 分类 | Folder |
| AI 整理 | Sparkles / 品牌折角图形 |
| 搜索 | Search |
| Skill | Blocks |
| 导入 | File Plus |
| AI 概括 | Panel Top |
| 来源溯源 | Link |
| 分享 | Share |
| 更多操作 | Ellipsis |

### 5.3 图标使用规则

- 同一页面不混用不同风格的图标。
- 不使用大量彩色拟物图标。
- 不使用过度复杂的 3D 图标。
- AI 功能可以在通用图标的基础上建立品牌专属图形。
- 图标优先辅助信息理解，不替代必要的文字说明。

## 06. 布局与间距系统 Layout & Spacing

### 6.1 布局原则

整体采用：

**内容优先、轻量容器、清晰层级、适度留白**

收藏内容允许丰富，操作区域应保持简洁。

不通过堆叠大量背景色、描边和阴影来组织页面。

### 6.2 间距系统

采用 4px 基础单位。

标准间距：

`4 / 8 / 12 / 16 / 24 / 32 / 40 / 48`

| 场景 | 建议间距 |
|---|---|
| 页面左右边距 | 20px |
| 双列卡片间距 | 12px |
| 卡片内部间距 | 12–16px |
| 模块内部间距 | 12–16px |
| 主要区块间距 | 24–32px |
| 图标与文字 | 8px |
| 标题与辅助信息 | 4–8px |

### 6.3 圆角系统

| 元素 | 圆角 |
|---|---|
| 小型标签 | 8px |
| 按钮 | 12px |
| 普通卡片 | 16px |
| 弹层 | 20–24px |
| 大型功能容器 | 20px |
| 胶囊组件 | Full Rounded |

圆角以统一、柔和为主。

避免整套产品到处使用过大的圆角，导致有效信息空间缩小。

### 6.4 阴影与边框

默认优先使用：

- 浅色边框
- 背景颜色区分
- 间距分隔

常规卡片可不使用阴影。

弹层、悬浮面板、重要浮动操作可使用轻阴影：

`0 4px 20px rgba(32,38,32,0.06)`

避免浓重阴影、玻璃拟态、霓虹描边。

## 07. 卡片系统 Card System

FavToSkill 应针对不同内容建立三套卡片视觉规则。

### 7.1 分类卡片 Category Card

#### 核心定位

帮助用户快速理解 AI 整理后的收藏内容分布。

#### 视觉形式

**图片拼贴 + 分类名称 + 收藏数量**

建议：

- 使用双列卡片布局。
- 顶部展示 2×2 的内容封面拼贴。
- 下方展示分类名称与数量。
- 卡片背景为白色。
- 圆角 16px。
- 封面区域适度裁剪，保持整齐。

示例：

**AI 效率工具**

32 条收藏

#### 设计原则

- 以真实内容作为主要视觉。
- 不使用巨大的文件夹图标。
- 不给所有分类分配随机高饱和颜色。
- 不增加不必要的装饰图形。

### 7.2 收藏内容卡片 Collection Card

#### 核心定位

展示用户原始收藏的视频、图文及其他内容。

#### 视觉形式

**内容封面 + 标题 + 来源信息**

建议：

- 优先使用双列瀑布流。
- 视频封面可使用 4:5 比例。
- 标题最多两行。
- 显示必要的来源平台和辅助信息。
- 保持原始内容的视觉丰富性。

#### 设计原则

收藏内容是页面主角。

不要额外使用大面积品牌色覆盖原始封面。

对于包含关键信息或文字的图片，避免过度裁切。

### 7.3 Skill 卡片

#### 核心定位

展示由收藏知识形成的可复用能力。

Skill 不应简单复用原始收藏卡片的结构。

#### 视觉形式

**能力图标 + Skill 名称 + 功能描述 + 使用入口**

示例：

**旅行规划助手**

根据预算、时间和偏好，帮助生成个性化旅行路线与行程安排。

基于 18 条收藏生成

操作：开始使用

#### 设计规则

- 白色卡片。
- 16px 圆角。
- 小面积浅绿色作为能力标识背景。
- Skill 名称突出。
- 描述强调可以完成的任务。
- 操作入口清晰。
- 保留来源收藏的关联信息。

#### 核心区别

收藏卡片回答：

**我收藏了什么？**

Skill 卡片回答：

**这些知识可以帮我做什么？**

## 08. 基础组件系统 Components

### 8.1 按钮 Button

#### Primary Button

用于普通主要操作：

- 深墨色背景 `#202620`
- 白色文字
- 高度 48px
- 圆角 12px

#### AI Primary Button

用于 AI 整理、生成等核心 AI 操作：

- 青柠绿背景 `#D5F57A`
- 深墨色文字
- 可搭配 AI 图标
- 高度 48px
- 圆角 12px

#### Secondary Button

用于普通次级操作：

- 白色或透明背景
- 轻边框
- 深墨色文字

#### Text Button

用于：

- 查看全部
- 展开
- 编辑
- 了解更多

按钮应具备默认、点击、禁用、加载等状态。

### 8.2 搜索与输入框

- 背景：白色或浅灰色。
- 圆角：12–16px。
- 高度：48–52px。
- 左侧可放置搜索图标。
- 占位文字使用次级文字色。

示例：

`搜索你的收藏...`

AI 输入框：

`问问你的收藏夹...`

### 8.3 标签 Tag

使用轻量胶囊样式。

普通标签：

- 浅灰背景
- 深灰文字

选中标签：

- 深墨色背景
- 白色文字

AI 类型标签：

- 浅绿色背景
- 深色文字

标签应尽量短，避免承担大段文字。

### 8.4 AI 提示卡片

AI 提示卡片统一采用：

- 浅绿色背景 `#EFF8D8`
- 适量内边距
- 小型 AI 标识
- 标题 + 简短说明
- 必要时提供单个主要操作

示例：

**帮你整理好了**

新发现了 3 个知识分类。

不要在每一个 AI 提示中都放置夸张的插画。

## 09. 核心页面视觉规范

### 9.1 收藏首页 Home

#### 页面目标

让用户快速了解自己的收藏分类，并能继续整理和查找内容。

#### 推荐信息层级

1. 顶部欢迎语或页面标题
2. 搜索收藏入口
3. AI 智能整理入口
4. 收藏分类筛选
5. 分类卡片网格
6. 底部导航

#### 视觉重点

- 整体使用暖白背景。
- AI 整理入口采用浅绿色容器或品牌色按钮。
- 分类卡片使用两列图片拼贴。
- 顶部保持轻量，不堆砌装饰。
- 避免占用过多首屏空间。

### 9.2 分类详情 Category Detail

#### 页面目标

帮助用户理解某一类收藏的整体内容，并查找对应资料。

#### 推荐信息层级

1. 分类标题及收藏数量
2. AI 自动概括区域
3. 内容类型筛选
4. 双列收藏瀑布流
5. AI 问答入口

#### 视觉重点

AI 概括使用浅绿色信息区域。

原始内容使用白色卡片或无明显容器的瀑布流。

AI 概括可折叠，避免占据过多浏览空间。

### 9.3 AI 问答 AI Chat

#### 页面目标

让用户通过自然语言直接调用收藏内容中的知识。

#### 视觉特点

- 保持聊天界面的简洁性。
- 用户消息使用适度强调的背景。
- AI 回答以可读性为主。
- 引用来源使用独立的内容卡片。
- AI 回答与原始来源建立明确联系。

#### 重要原则

**AI 的价值不只是回答问题，还要让用户知道答案来自哪些收藏内容。**

避免每条 AI 消息都增加过多品牌装饰。

### 9.4 Skill 列表 My Skills

#### 页面目标

集中展示用户已经获得的可复用能力。

#### 推荐信息层级

1. 页面标题「我的本事」
2. Skill 分类筛选
3. Skill 卡片列表
4. 新建 Skill 操作

#### 视觉特点

相比收藏页面更有序、更结构化。

不使用视频瀑布流，而使用统一的能力卡片。

每张卡片突出：

- 名称
- 核心用途
- 来源
- 调用入口

### 9.5 Skill 详情

#### 页面目标

让用户理解 Skill 的能力并快速开始使用。

#### 推荐结构

1. Skill 图标与名称
2. Skill 简介
3. 可以完成的任务
4. 使用示例
5. 来源收藏
6. 主要操作「开始使用」

#### 视觉重点

- 顶部可使用轻量的品牌色强调。
- 内容区域保持白色与暖白。
- 主要操作使用深墨色按钮。
- Skill 内容采用结构化排版。
- 避免复杂技术术语直接暴露给普通用户。

### 9.6 收藏导入

#### 页面目标

降低收藏内容导入产品的操作成本。

#### 视觉特点

- 展示用户可理解的导入方式。
- 使用简单的列表或选择卡片。
- 突出下一步操作。
- 清晰说明导入状态。

#### 处理状态

需要具有：

- 等待导入
- 正在导入
- AI 正在整理
- 整理完成
- 导入失败

状态必须明确，避免单纯通过循环动画让用户等待。

## 10. AI 视觉交互语言

### 10.1 AI 视觉定位

AI 应是轻量、聪明、随时可以使用的助手。

它不应该成为整个产品的唯一主角。

品牌重点是用户的收藏与能力增长，而不是机器人本身。

#### AI 主要视觉特征

- 青柠绿
- 浅绿色背景
- 品牌书签图形
- 卡片聚合与展开动画
- 清晰的处理状态
- 简短自然的反馈文案

### 10.2 AI 能力入口

AI 入口应出现在用户需要它的场景中。

例如：

- 首页：整理收藏
- 分类详情：概括内容、生成 Skill
- 搜索场景：智能问答
- Skill 页面：调用已有能力

不建议将所有 AI 功能集中在单独的复杂 AI 工作台中。

### 10.3 拟人化助手

原项目存在拟人化 AI 助手的设计概念。

新品牌建议适度弱化角色化表达。

如果保留拟人化元素，应限制在：

- 首次引导
- 空状态
- AI 处理中
- 整理成功的轻量反馈

不建议在每个页面常驻大型 AI 角色。

## 11. 动效系统 Motion System

### 11.1 动效原则

关键词：

**轻、快、自然、有意义**

动效需要帮助用户理解：

- 内容如何被整理。
- AI 是否正在处理。
- 操作是否成功。
- 内容如何转化为 Skill。

避免纯装饰性的大量动画。

### 11.2 基础动效时长

| 类型 | 时长 |
|---|---|
| 按钮状态 | 120–180ms |
| 标签切换 | 150–200ms |
| 卡片过渡 | 200–300ms |
| 弹层出现 | 220–320ms |
| Skill 生成反馈 | 450–650ms |

以上为建议值，应根据实际交互测试调整。

### 11.3 核心品牌动画

#### AI 整理

内容卡片轻微聚拢，逐步进入对应分类。

最终出现整理完成反馈。

#### Skill 生成

若干收藏卡片逐步收拢、重组为结构化 Skill 卡片。

完成后书签折角展开，代表能力形成。

#### 收藏成功

使用轻量的书签填充或缩放动画。

#### AI 问答

用清晰的加载状态和渐进式内容呈现传达处理进度。

### 11.4 动效限制

- 不使用持续跳动吸引用户点击。
- 不频繁使用大型全屏动画。
- 不为了装饰而延长任务完成时间。
- 支持系统减少动态效果设置。

## 13. 响应式与无障碍规范

### 13.1 移动端优先

优先适配常见移动端屏幕。

- 布局使用弹性宽度。
- 保持一致的左右边距。
- 优先保持双列收藏布局。
- 屏幕较窄时适当缩减间距。

- 文字与背景保持足够对比度。
- 支持动态字体及文本放大。
- 主要操作点击区域不小于 44×44px。
- 为纯图标操作提供无障碍名称。
- 加载、错误、成功状态使用文字说明。
- 不使用颜色作为唯一的信息载体。
- 支持减少动态效果。

## 14. 视觉禁用规则

为了避免后续页面生成产生风格漂移，以下设计不应作为产品的默认风格。

#### 不要采用

1. 大面积紫色、蓝色 AI 渐变。
2. 复杂玻璃拟态和高亮模糊效果。
3. 大面积黑色背景的科技风格。

6. 过度游戏化的界面。
7. 所有卡片都使用高饱和背景。
8. 过大的按钮、图标和留白。
9. 多层级强阴影。
10. 缺乏必要信息的极简设计。

#### 推荐保持

1. 干净温暖的亮色界面。
2. 青柠绿作为有限的品牌强调。
3. 真实收藏内容主导视觉。
4. 统一圆角与图标体系。
5. 清晰、紧凑但不拥挤的信息密度。
6. 通过卡片、层级与留白建立秩序。
7. AI 交互有明确状态反馈。
8. Skill 具备独立、清晰的视觉识别。

## 16. 后续 UI 生成与开发约束

当使用 Figma Make、Codex 或其他 AI Coding 工具生成 FavToSkill 界面时，需要遵守以下原则：

1. **统一品牌**：所有页面使用相同的颜色、字体、圆角、间距和图标系统。
2. **保持内容优先**：不要为了视觉美观而弱化真实收藏内容。
3. **组件复用**：分类卡片、收藏卡片、Skill 卡片分别建立统一组件。
4. **移动端优先**：布局应优先考虑真实手机尺寸。
5. **AI 能力清晰**：让用户直观知道 AI 能做什么，以及当前正在做什么。
6. **不过度设计**：不增加与实际用户任务无关的装饰和复杂交互。
7. **状态完整**：考虑加载、空状态、失败、成功、禁用等必要状态。
8. **易于维护**：颜色、圆角、排版和组件必须通过统一 Design Tokens 管理。
9. **避免风格漂移**：新增页面必须遵循本规范，不自行引入新的主色和视觉体系。
10. **优先保证可用性**：当视觉表达与内容理解、操作效率发生冲突时，以可用性为先。

## 17. 最终设计总结

FavToSkill（藏点本事）的视觉语言不应简单模仿传统知识管理软件，也不应被塑造成过度娱乐化的内容社区。

它应该兼具：

- **收藏工具的轻松感**
- **个人知识空间的秩序感**
- **AI 产品的聪明感**
- **年轻品牌的趣味感**

最终形成三个明确的视觉层次：

**第一层：原始收藏内容真实而丰富。**

通过封面、图文、瀑布流等形式，保留用户熟悉的内容浏览体验。

**第二层：知识整理过程简单而有序。**

通过统一卡片、结构化信息、清晰分类与低干扰操作，降低知识管理的使用门槛。

**第三层：AI 转化过程轻巧而有趣。**

通过青柠绿品牌色、几何折角图形与轻量动效，让用户感受到内容从收藏转化为可复用能力的过程。

### 设计核心原则

> **让用户感觉自己拥有了一个更聪明、更好用的收藏夹，而不是又多了一个需要学习的知识管理软件。**

这应成为 FavToSkill 后续品牌设计、界面设计和交互体验的统一判断标准。
